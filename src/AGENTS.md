# Frontend work guidance

## Ownership

- `app.js`: public GitHub data, commit-tree caching, snapshot fallback, projected 3D folder graph, search, file links, history, and drawers.
- `hologram.js`: the restored original graph aesthetic: 3D orbital/helix/hive positions, perspective orbit, gimbal rings, glowing hexagonal cores, targeting reticles, tendrils, and flowing energy.
- `filePreview.js`: independent holographic file windows, per-window requests, safe text/image previews, pointer and keyboard move/resize, tiling, maximize/restore, wrapping, and secondary GitHub navigation.
- `repositoryExplorer.js`: restored command deck below the graph, public repository selection, real commit/file telemetry, folder focus, tracked AGENTS.md previews, display controls, and exports.
- `walkthrough.js`: replayable four-step help, contextual control highlights, keyboard navigation, and dismissal with focus returned to its trigger. It does not modify repository, folder, page, query, history, camera, or file panes.
- `styles.css`: full-viewport layout, desktop/phone adaptation, original cyan/gold/acid themes, focus and other interaction states.
- `engine/`, `visualizers/`, and `audio/` contain the original experimental modules. The live application does not import them.

## Contracts

- `hologram.js` renders ARC-XENO fusion (default), J.A.R.V.I.S. tactical (blue optics, angular glyphs, circuit links, grid), and MUTHUR bioscan (green organic spores, curved tendrils, scanner sweep). Preserve these restored lenses. Topologies use folder orbital clusters, two intertwined helix strands, and spherical hive cells. Guides are decorative, never invented dependency links.
- `graphView.js` defaults to one folder at a time with 24 immediate items plus the root. Expanded mode optionally keeps complete nested hierarchy within the absolute 80-node cap. Folder nodes show actual matched descendant counts; paging reaches every child. Root paths, Up one folder, query filters, and selection changes must stay consistent. Never truncate the underlying file dataset.
- `viewCache.js` caches validated, exact-commit file metadata and history, never source contents. Keep at most three repo trees and two million serialized characters in total, with a one-million-character limit per tree. Evict only this cache's own entries. Cache failures must not break workspace preferences or live viewing.
- Explain the map through a location heading, plain-language instructions, counts, and a folder/file legend. Tabbed folders mean navigation; other file glyphs mean preview. Preserve the original multicolor ARC-XENO, cyan/gold J.A.R.V.I.S., and acid/mint/amber MUTHUR palettes for nodes and connections. Colors are visual accents, not a file-type key. Prioritize folder labels and try multiple collision-free label positions. Instruments remain subordinate to the file map. ARC-XENO uses a segmented reactor, J.A.R.V.I.S. a blue optical core and targeting brackets, MUTHUR its organic scanner. New workspaces do not auto-rotate; retain existing explicit camera settings.
- How to use this opens automatically for first-time visitors and remembers Done, Close, trigger dismissal, or Escape in browser storage under xeno-stark:walkthrough:v1. Storage failures must not break help. It remains nonmodal, replayable, and has Back/Next/Done plus Close and Escape. Arrow keys navigate only when focus is inside the guide. Escape closes help before graph shortcuts can clear the user's filters. Highlight the actual controls and keep the timeline visible during its step on phones. Remove all highlights on dismissal and return focus to the help button.
- The command deck previews the actual graph beside its selectors. Render that secondary canvas only while visible. Sector clusters browse/search files in place with bounded results and explicit pagination. Only Focus in graph or projecting a file navigates upward.
- Persist validated camera yaw, pitch, zoom, and orbit state with workspace settings. Debounce manual changes, periodically save orbit progress, and flush on pagehide/hidden. Do not reset the camera during repository loads. Keep reset/zoom/rotate buttons working.
- Display actual selected-repository commit authors with explicit authorship labels; app branding is separate.
- Summon the holographic preview from node and Files clicks. Fetch immutable raw content at the selected commit SHA; retain Open on GitHub as a secondary link. Insert source text with DOM text APIs; keep HTML and scripts inert. Bound text/image sizes and cancel stale requests.
- Preserve the current graph on API failure. Guard async requests so an old repository or timeline selection cannot replace a newer one.
- A cached pre-preview HTML shell must migrate once to a fresh shell before initializing. Keep the query's repository selection and avoid reload loops.
- Real folder structure determines edges. Hover and Files expose full paths when labels collide.
- File panes are nonmodal so users can open several files and still operate the graph. Each pane owns its request and geometry. Focus brings it forward; Escape dismisses the focused pane. History/repository changes close all panes. Preserve graph orbit pause while panes are open.
- Wrap source lines by default, including long tokens. Provide a per-pane Wrap toggle, title-bar drag, edge/corner resize, maximize/restore, Tile files, and keyboard arrow controls for title bars and resize grips. Clamp panes to the workspace after viewport changes.
- Save the last selected repository pointer under xeno-stark:workspace:v1 (version 2). Save validated theme, topology, camera, and navigation (folder, zero-based page, search) independently under xeno-stark:workspace:v2:<lowercase owner/repo>. Save outgoing settings before changing repositories, then restore the target settings and both control sets. Migrate legacy global version 1 settings only to their owning repository. Obsolete classic settings map to fusion; new repos default to fusion/orbital. An explicit valid repo query overrides the saved pointer. Tolerate unavailable or malformed storage and retain session preferences in memory when storage is restricted.
- Preserve pending folder/page/search while repository data loads, including startup snapshots. Reconcile navigation only after a real file tree arrives. A removed folder falls back to its nearest surviving ancestor; a page beyond the available range clamps to the last page. Search is saved too so a filtered page restores consistently. Navigation changes share the debounced workspace save and lifecycle flush.
- Save selectedCommitSha independently of the current history index, so outgoing history cannot contaminate a newly selected repo. Restore from the cached exact tree when available; otherwise fetch a saved commit outside the recent 40 through GitHub's commit endpoint. Snapshot startup must not briefly select the latest commit over a remembered one. A missing commit may fall back to latest only with a visible explanation. Failed loads retain the selection. New commits do not move the user's selected SHA or close existing panes when that SHA is unchanged.
- Bound the Files drawer to batches of 100 and Sector clusters to batches of 40. Folder search covers all folders; file search covers the full repository. Cache folder counts per file dataset to avoid rescanning every folder against every file.
- Save open panes, immutable commit references, geometry, stacking order, wrapping, and maximize/restore state in browser localStorage per repository. Debounce moves and flush on pagehide. Restore once after initial data loading, without overwriting saved layouts during startup or repository transitions. Validate stored records and tolerate unavailable storage.
- Minimized panes stay open and retain requests and geometry. Dock buttons restore them; Show graph minimizes every visible pane. Only visible panes participate in tiling or active-node targeting. Persist minimized state with schema 2, migrating schema 1 viewport coordinates into workspace-relative coordinates.
- When automatic rotation is enabled, use the original slow orbit. Pause orbit when a node is hovered, stop it during manual drag, and respect reduced motion. Audio stays off. Normal wheel and vertical touch gestures must scroll the page. Ctrl/Command plus wheel and zoom buttons zoom; horizontal touch drags rotate. Keep native file links.
- The graph, header, and timeline occupy 84% of the viewport (minimum 420px), exposing the explorer below. The page scrolls to the repository explorer underneath. File windows use workspace-relative absolute positions so they scroll away with the graph; previews opened from the explorer return to the graph. Drawers remain dismissible overlays.

## Verification

Run `node --check src/app.js` and `node --test src/graphView.test.js src/viewCache.test.js`. Exercise canvas-node navigation, search and empty results, folder focus and paging, large repositories, switching independent repo workspaces, exact commit restoration (including outside the recent list), drawer keyboard access, history/playback, API failure, cached reloads, and desktop/phone layout in a real browser.

- On page load and repository switch, ignite the core and stagger nodes into their saved layout over about five seconds, with spiral movement, a gentle pop and fading arrival rings. Do not reset the saved camera or replay on background data refresh. Reduced motion shows the complete graph immediately. Hidden nodes must not receive pointer hits.

- History now autoplays from the oldest available commit after repository loading, loops after the latest, and holds each version for 3.2 seconds at 1x with a 1.8-second smooth transition. Manual history selection, opening a file, pause, background tabs, and failures stop playback. Use a playback generation guard to prevent stale async timers. Reduced-motion visitors start paused. The explicit autoplay behavior supersedes restoring the selected commit as the initial resting view; manual selections are still saved.
- Commit changes replay the spiral/pop assembly. Lens colors must apply to page surfaces, panels, chamber illumination, file windows and the command deck as well as graph glyphs and text.

- Playback speed (0.25, 0.5, 1 or 2) is saved per repository with workspace preferences; default 1. Speed controls commit dwell time and the next transition duration. Changes while playing reschedule the pending tick.
- History transitions preserve nodes by path and interpolate from their displayed positions with smooth easing. Only new nodes pop in; removed nodes dissolve without hit targets. Sample interrupted transitions before starting the next; never replay the full ignition for every commit. Reduced motion lands immediately.

- changes.js compares complete previously displayed and next trees by path and object SHA/type/mode. Added, Changed, Removed counts describe that comparison, not an inferred parent diff. Initial views and playback wrap are baselines, not mass deletions. Renames are explicitly remove + add.
- Preserve theme node colors. Persistent text markers identify changed files; folder markers mean changed contents. Removed visible nodes carry a Removed label while dissolving. The compact timeline summary opens a bounded, keyboard-accessible full-repository change list and pauses playback. Removed entries are not current-file links.

- Changed-file clicks open a before/after code comparison in the existing draggable/resizable/minimizable window system. Compare the exact previously displayed SHA with the selected SHA, persist both references, fetch bounded inert text, align line numbers, and label additions/removals. Never treat a failed old-file fetch as empty content. Binary/oversized comparisons explain the limit.
- Normal playback is now 3.2 seconds per commit, with 1.8-second position transitions; speed multipliers apply to both. ARC-XENO and JARVIS retain their base glyphs with additional orbit rings, segmented arcs and satellite lights.

- Diff windows have sticky Previous/Next change controls with a current/total count. Jump by contiguous edit blocks, scroll only inside the owning pane, highlight the selected block, and disable controls at the ends or for unchanged text. Controls remain usable after wrapping, resizing and minimizing.
- Text backgrounds toggles graph label backplates, including Removed labels. It defaults off and persists independently per repository; keep the panel and code-reading surfaces intact.

- Persist selectedChange (zero-based edit block) with each diff pane and its immutable before/after references. Validate on restore, clamp after diff loading, and align the saved block when a minimized pane returns. Missing values default to the first block. Restored file panes keep history paused so autoplay cannot immediately close the restored workspace.

- Each diff has a Show only changes toggle, off by default. Persist onlyChanges as a strict boolean with that pane. Hide unchanged rows while retaining original line numbers, edit-block navigation and selected block; show omission counts between blocks so separate edits do not look contiguous. Restoring a minimized pane applies both its filter and edit position.

- Hidden unchanged-line separators are keyboard-operable buttons that independently expand/collapse their own context while Show only changes stays enabled. Keep expanded context scoped to the loaded comparison and preserve edit navigation.
- Start/reset at zoom 1.2. Migrate the former untouched zoom 1 once, marked with cameraFramingVersion; preserve all other saved zoom choices. Camera readouts use plain Turn and Tilt labels.
- JARVIS file nodes are distinct circular optical modules with calibrated ticks, fixed gold corner brackets and a rotating scan arc. Preserve ARC-XENO and MUTHUR designs.
